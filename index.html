P.01
EMNLP 2026UNDER REVIEW

SQLEq-O1

面向 SQL 等价验证训练可本地部署的轻量推理模型。方法不把有限实例上的执行一致或表面结构相似当作语义证据，而是用形式化标签、验证式推理蒸馏和可验证奖励学习等价与不等价的决策边界。

60KCoRE-SQL 89.38LeetCode-Hard GM 1.5BCompact Verifier
问题

执行测试只能说明两条查询在有限数据库实例上结果相同，无法证明语义等价；VeriEQL 等 SMT 验证器面对深层嵌套、聚合与复杂关系组合时又容易出现状态空间爆炸。提示式大模型推理成本较高且输出不稳定，小模型则容易把关键词共现或结构重合学成捷径。

方法

数据侧采用双轨构造：一条轨道挖掘 LeetCode 同题的人写多解，保留真实查询的组合复杂度；另一条从 SynSQL 出发，由多个 Text-to-SQL 模型生成候选并在实例内配对，以扩充难负例。所有查询对由 VeriEQL 给出形式化标签，再蒸馏并筛选与标签一致的验证式推理，按类别平衡形成 60K 对 CoRE-SQL；训练采用 30% SFT Warm-up 与 70% GRPO，稀疏奖励只检查答案标签和输出格式。

结果

在 Qwen2.5-Coder-1.5B 上，GRPO 将 LeetCode-Hard 的 GM 从全量 SFT 的 73.60 提升至 89.38；在来源隔离的 Calcite+Spider-DAIL 上取得 76.77 GM，两个测试集平均 GM 达 83.08。消融结果表明，形式化难例、显式推理轨迹与强化阶段的边界校准均带来稳定收益。

P.02
EMNLP 2026UNDER REVIEW · ARXIV

UniQL

UniQL 关注同一自然语言意图在异构数据库中的方言实现，而不是把不同数据库上的不相关样本混合比较。基准在 Schema 与数据内容对齐的前提下，为每个问题提供 16 种可执行 SQL。

16SQL Dialects 24,544Executable SQL 20.14%Best All-16
问题

现有 Text-to-SQL 基准长期集中于 SQLite，但真实数据库在类型系统、内置函数、标识符规则和执行语义上存在明显差异。若不同方言使用不同问题与数据，就无法区分模型究竟受困于问题本身，还是缺乏对目标方言的理解。

方法

以 BIRD Dev 的 1,534 个问题为共同语义锚点，将原数据库迁移到 15 个目标系统，并处理类型映射、命名空间和标识符差异。SQL 先由 SQLGlot 转换，失败样本再进入 LLM 翻译与最多三轮执行反馈修复；重复失效模式被整理为方言规则继续迭代，长尾样本由两名标注者独立校验并达成共识。构建和评测均采用保守 EX，显式保留排序语义与重复项计数。

结果

最终得到覆盖 16 种方言的 24,544 条人审可执行 SQL。最佳模型平均 EX 仅为 54.63%，同一问题在全部 16 种方言上同时正确的比例最高只有 20.14%；模型在 SQLite、Oracle、Teradata 等系统间还呈现显著波动，说明单方言成绩不能代表跨数据库泛化能力。

P.03
NDBC 2026ACCEPTED

FAR-SQL

将 SQL 等价判定划分为形式化确定域与模型补全域：先依据历史运行画像估计不同结构查询的验证收益，只有当 VeriEQL 无法给出确定结论时，才由任务适配的本地小模型接手。

83.98OOD GM 0%Undetermined 13.97sAverage
问题

VeriEQL 给出的 equivalent/inequivalent 结论具有明确的形式化来源，但在复杂聚合、嵌套与方言函数上常出现 timeout、unsupported 或 conversion error。统一延长预算会让低收益样本持续占用求解时间，直接改用模型又会抹去形式化结论与模型判断之间的可信边界。

方法

离线阶段从历史 VeriEQL 日志学习“SQL 结构—时间预算—确定率”的验证收益画像，并以来源隔离的形式化标签数据监督微调 1.5B/1.7B 本地模型。在线阶段按边际收益动态分配验证预算，保留所有确定输出；对 timeout、unsupported、runtime error、conversion error 等状态分别归一化和构造提示，仅在非确定区域调用模型，并以 Self-Consistency@3 返回稳定多数结果。

结果

在 412 对 Calcite+Spider-DAIL 域外样本上，FAR-SQL + Qwen2.5-SFT 达到 83.98 GM，较纯 SFT 的 76.20 提升 7.78 个百分点；未决率降至 0，平均耗时为 13.97 秒。相比 VeriEQL@60s 的 38.19 GM 与 35 秒平均耗时，动态路由同时改善了覆盖、均衡性和验证成本。

EVALUATION INFRASTRUCTURE · FINTECH AGENT

S.01

SQL EVALUATION INFRASTRUCTURE

统一 SQL 评测与执行框架

为 NL2SQL、SQL 纠错与 SQL 等价验证提供同一个可复现实验入口，把原本散落在各任务中的样本适配、数据库执行、结果比较和指标汇总收敛到统一流水线。

多任务统一抽象 三数据库自动切换 EX 横向对比
架构
任务层只描述样本如何构造、预测 SQL 从何处读取以及目标结果如何取得；公共执行层统一负责连接数据库、运行查询、比较结果和聚合指标。模型、数据集与任务定义通过适配器接入，评测主流程不再随实验对象重复改写。
方法
以 EX 为核心指标，在 Docker 中维护 MySQL、PostgreSQL 与 SQLite 的标准化环境并按任务自动切换；对执行结果、空值、顺序、异常与超时采用一致的数据结构和统计口径，使不同模型和数据集的结果可以直接横向比较。
结果
同一流水线能够覆盖多模型、多任务与多数据集实验，减少重复的执行脚本和临时统计代码；新增任务主要集中在适配层，将一套新评测从天级准备缩短到小时级。
S.02

BANKING FINTECH · MULTI-AGENT

CreditRiskRobot

面向企业贷款授信审查的辅助工作台，从材料盘点开始，依次完成财务指标计算、经营与还款来源分析、风险汇总、证据引用和报告自审计；系统提供审查依据，不替代人工审批。

五类材料统一解析 多 Agent 风险协作 证据回链与自审计
架构
以 Case 为数据边界，材料清单、文档解析和证据索引先形成统一上下文，再由企业画像、经营、财务、现金流、担保与外部风险 Agent 分工分析，Risk Summary 与 Credit Opinion 汇总审查意见。报告端复用 FinSight 的 outline → section → report 结构并适配企业授信提纲。
方法
统一接收 PDF、DOCX、XLSX、TXT 与图片，自动分类并对照授信材料清单标记缺口；财务指标采用规则计算，风险项保留来源文件与材料依据。Report Audit 检查免责声明、无证据风险和越权审批表述，人工可在导出前编辑全文。
结果
形成从多 Case 管理、材料盘点、多 Agent 分析到 Markdown、HTML、Word、PDF 报告导出的完整工作流，并提供公开资料案例验证材料缺口识别。所有输出均定位为辅助审查，最终授信条件和审批结论保留给人工。
